# scholarship 테이블 현재 등록 목록 (중복 확인용)

이 파일은 실행되는 코드가 아니라, `scholarship` 테이블에 이미 들어간 장학금을 추적하기 위한 기록입니다.
새로운 장학금을 크롤링/수집해서 넣기 전에 이 목록과 이름+기관 기준으로 대조해서 중복을 피합니다.

**중요**: 새 배치를 실제로 DB에 INSERT한 뒤에는, 이 파일에도 그 배치를 반드시 추가할 것 (안 그러면 다음 대조가 부정확해짐).

마지막 업데이트: 2026-07-27 (총 133건 — 2026-07-27 실제 DB(Supabase, read-only 직접 연결)와 대조해서 이 파일의 배치별 표와 100% 일치 확인, 기존에 적혀있던 "117건"은 예전 요약 집계 오류였음(배치별 기록 자체는 문제 없었음). 이번 확인으로 신규 채택 없음. 충남대학교 크롤링 전체 완료(80건) + KAIST 배치1~5 완료(37건, 총 117건). 2026-07-26: HWP/OCR 도구 도입 후 CNU 쪽 "수동 확인 필요" 5건(첨부 HWP/이미지) 재확인 — 전부 이미 마감/정적안내문으로 최종 미채택, 목록 정리. 2026-07-27: KAIST 배치5 — "수동 확인 필요" 4곳 중 2곳(생명과학과·문술미래전략대학원)은 UA 헤더 재요청으로 해결(신규 0건), 나머지 2곳(산업디자인학과 WAF차단, 학생포털 SSO)은 사용자가 직접 확인 필요. CNU 쪽 남은 수동 확인 대상은 서버 접속 불가 3건(건축학과·식물자원학과·cnuceramics.net))

**2026-07-31 description 보정**: `description`에 "직접 확인 필요"/"불명확"/"확인 못함" 같은 표현이 남아있던 5건(id 6, 77, 79, 80, 91 — 대전 인재육성 장학사업, 의암 손병희 우수논문 장학생, 3.1장학생(박사과정), 엔젤루트 일본어학연수 학비지원, 농촌출신대학(원)생 학자금대출)을 각 기관 공식 페이지/공고문을 직접 찾아서 실제 자격조건·금액·일정으로 교체함(DB `description`/`application_period` 직접 UPDATE, 신규 INSERT 아님 — 스키마 변경 없음). id 6(대전 인재육성)과 id 79(3.1장학생)는 2026년 세부 소득분위/커트라인이 아직 공고 전이라 완전히 못 채움 — 남은 부분은 매년 4월/9월(대전) 또는 재단 문의(3.1장학생) 시점에 갱신 필요.

**2026-07-31 "확인 필요" 문구 전면 정리 (신뢰도 개선)**: 사용자 화면에 "확인 필요"라는 표현이 그대로 노출되면 서비스 신뢰도가 떨어진다는 피드백에 따라, DB 전체에서 이 표현을 검색해 정리함.
- `application_period`(마감일): 68건이 "확인 필요" 계열이었음 — 이 중 65건은 전부 충남대 신입생/재학생 정기 장학금(같은 출처 페이지, `support_030302.html`)이라 "매 학기 초 공지 (충남대 홈페이지 확인)"으로 일괄 교체. 나머지 3건(대전 관련 2건 + 대전 청년도전지원사업 1건)은 개별 확인해서 실제로 알아낸 내용(상시/분기 접수 추정, 연 1회 모집, 2026-01-01~12-31 상시 신청 등)으로 교체.
- `description`: 9건에 "...확인 필요"가 문장 일부로 남아있던 것을 "OO 홈페이지 공고 기준/참고"처럼 사실은 그대로 두고 표현만 바꿈(새로 지어낸 정보 없음).
- `major`/`min_credits`/`admission_score_condition`/`headcount`(참고용, 매칭 미반영 필드): 값이 순수하게 "확인 필요"뿐이던 39건은 실질 정보가 전혀 없는 값이라 `README.md` 관례("모르면 비워둠")에 맞춰 NULL 처리(프론트에서 값 있을 때만 표시하므로 자동으로 안 보이게 됨). 예외로 "확인 필요 (대학별 상이)" 1건은 "대학별 상이"로 정보만 남기고 교체.
- `grade_level`/`affiliated_institution`(레거시 원문 필드, 프론트에서 아예 안 씀) 2건은 그대로 둠 — 화면에 노출 안 되는 죽은 필드라 정리 대상 아님.
- 최종 확인: 사용자에게 실제로 보여지는 모든 필드(name/provider/description/application_period/major/min_credits/admission_score_condition/headcount/eligible_university/eligible_college) 기준으로 "확인 필요" 잔여 0건.

**구조 개요**: KAIST는 CNU와 달리 단과대학/학과별 개별 홈페이지·게시판 순회 구조가 아니라, 중앙 학사정보 페이지(`www.kaist.ac.kr` 내 "장학안내" 섹션)에 전체 장학 제도가 표 형태의 정적 페이지로 통합 정리되어 있음. 다만 실제 개별 장학금 "공고문"(외부 재단 모집, 신청기간 안내 등)이 게시되는 실질적인 게시판은 학생 포털(`portal.kaist.ac.kr`) 내부에 있으며, 이 포털은 SSO 로그인이 반드시 필요해 비로그인 상태로는 접근 불가함(로그인 페이지 `portal.kaist.ac.kr/common/login/login.do`로 강제 리다이렉트, 로그인 없이는 카이스트뉴스/연구뉴스/캠퍼스 편의시설 링크 정도만 열람 가능하고 장학 공지 게시판은 노출되지 않음). 또한 학과 단위(예: `cs.kaist.ac.kr`, `ee.kaist.ac.kr` 등)에도 자체 공지/채용 게시판이 있어 기업연계 장학생 모집 등이 공개로 게시되는 경우가 확인됨(예: `ee.kaist.ac.kr/jobs`의 삼성SDI 박사/장학생 채용 안내) — 이는 CNU의 "학과별 게시판" 구조와 유사하며, 이번 배치에서는 처리하지 않고 다음 배치로 넘김.
