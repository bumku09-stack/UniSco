# 데이터 작업 인수인계 (2026-08-12)

**이 문서는 순수 데이터 작업만 정리한 것** — 코드/로직/도구 변경이 필요한 건 여기 없음(그건
개발 쪽에서 처리). 전부 **Supabase Studio(Table Editor)에서 웹사이트 원문 보고 칸 채우는
작업**이라, 코드나 SQL 몰라도 됨. 입력 방법은 `supabase/README.md` 맨 위 섹션 참고.

작업 원칙은 항상 동일 — `supabase/data_collection_guide.md`의 "절대규칙" 참고, 특히:
**확인 안 되면 추측해서 채우지 말고 빈 칸으로 둘 것.**

---

## A. 신청기간(`application_period`) 재확인 — 15건

`supabase/audit_reports/2026-08-12_stale_application_period.md`에 링크 다 정리돼 있음.
각 링크 들어가서 해당 연도(2026년 이후) 최신 모집 일정을 찾아서 `application_period` 칸을
갱신하면 됨. 못 찾으면(아직 공고 안 남 등) 그냥 두거나 "아직 공고 안 남"이라고만 적어도 됨
— 날짜 지어내지 말 것.

## B. 마감일(`application_deadline`) 확정 — 200건

`supabase/audit_reports/2026-08-12_195309_deadline_url_gaps.md`의 **A그룹** 참고. 이미
DB에 있는 `application_period` 원문 텍스트에 날짜 힌트가 있는 건들이라, 새로 웹사이트 안
찾아봐도 되는 경우가 많음 — 원문 다시 읽고 확정 마감일(YYYY-MM-DD)이 명확하면
`application_deadline`에 입력.

**주의**: "매년 3월", "매 학기 초" 같은 반복 공고는 특정 연도가 아니니까 채우지 말 것 —
지금처럼 비워두는 게 맞음(그래야 계속 노출됨).

같은 리포트의 **B그룹**(328건, 날짜 힌트 자체가 없음)은 우선순위 낮음 — 급하지 않으면 안
건드려도 됨.

## C. 신청 링크(`application_url`) 없음 — 130건

같은 리포트의 **C그룹** 참고. 기관 홈페이지 찾아서 **실제 신청/공고 페이지**(메인 홈페이지
말고— 지난번 132건이 이 실수로 문제였음, `data_collection_guide.md` 체크리스트 22번
참고) 링크를 `application_url`에 입력.

## D. 대상 대학(`eligible_university`) — 지금은 안 해도 됨

지난번엔 이걸 우선순위 1번으로 잡았었는데, 다시 확인해보니 걱정할 상황이 아니었음 — 교내
장학금(`category_l1`이 `school_internal`인 것)은 661건 전부 대학이 정확히 채워져 있었고,
비어있는 294건은 전부 지자체·재단·국가장학금처럼 원래 대학 무관인 종류였음. **그냥 넘어가도
됨.**

---

## 우선순위

**A(15건) → C(130건) → B(200건)** 순서 추천 — A는 이미 목록이 좁혀져 있어서 제일 빠르고,
C는 "메인 홈페이지만 넣지 않기"만 주의하면 되는 단순 작업, B가 제일 많고 판단이 필요함.
